# Project 14 – Implementation of Security Mechanisms for NoSQL Databases

## Introduction
This mini project involves the study and implementation of security mechanisms in NoSQL databases. We selected MongoDB as the NoSQL database to explore authentication, access control, secure queries, and a comparison with relational database security. The project demonstrates how to deploy, secure, and query a NoSQL database in a controlled environment.

## Objectives
The main objectives of this project are:
- To deploy a NoSQL database instance (MongoDB).
- To implement user authentication and role-based access control.
- To design and execute secure database queries.
- To compare security mechanisms of NoSQL databases with those of traditional relational databases.

## Implementation Summary
The project is structured into multiple components:
- **Database Deployment**: A MongoDB instance was configured with enabled authentication and security settings.
- **Authentication and Access Control**: Users were created with specific roles (e.g., read-only, read/write) to enforce least-privilege access.
- **Secure Queries**: Python scripts were prepared to connect securely and execute queries only after authentication.
- **Comparison with Relational Database**: A conceptual comparison was made between MongoDB security mechanisms and those used in relational databases such as MySQL.

## Results and Outcomes
The implementation successfully demonstrated:
- Enforced authentication preventing anonymous database access.
- Role-based access control restricting operations based on user permissions.
- Secure query execution using Python and MongoDB drivers.
- Clear differences in configuration and enforcement between NoSQL and relational database security models.

## Conclusion
This project shows the importance of database security in NoSQL systems. By applying standard security mechanisms, such as authentication and access control, the project highlights how to protect data and restrict access. The comparison with relational database security clarifies the similarities and differences in approach between the two database paradigms.
